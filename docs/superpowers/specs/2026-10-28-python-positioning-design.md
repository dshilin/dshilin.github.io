# Статьи как доказательства навыков Python QA и автоматизации

Дата: 2026-10-28. Реализация по прямому поручению «проанализировать и сразу создать»; технические решения ниже выбраны ассистентом, отдельного принятия текстов нет.

## Задача и текущая архитектура

Связать обучение с понятными работодателю доказательствами: проблема → решение → проверка → границы результата. Целевые направления из текущего запроса: Python QA и Python-автоматизатор. Миссия v1 сохраняется; прежняя цель автоматизации с ИИ остается контекстом, но не ограничивает текущие Python-материалы.

Сейчас Hugo/Hextra: `/` и `/blog/` используют собственные шаблоны; `/docs/python/` — пустой черновой раздел; одна статья о pytest находится в `/blog/` и тоже имеет `draft: true`. Переносить ее URL не нужно. План десяти недель сохранен в `.author-voice/examples/2026-10-21-python-blog-prompt/01-source.md`. В чтении чата «Подготовка к Python QA собеседованию» от 2026-10-28 подтверждено продолжение генераторов; результаты нового задания еще не проверены. В локальном учебном каталоге доступны код `group_cases`, тесты и `failed_names`. Наличие файла не доказывает самостоятельное авторство или успешный запуск.

## Выбор подхода

- Только изменить описания: быстро, но не дает устойчивого процесса новых публикаций.
- **Выбран ассистентом:** рабочая карта компетенций, редакционная карточка доказательств, Hugo archetype, автоматическая подборка статей и черновой Python-раздел. Подходит к существующему сайту и не требует новой платформы.
- Массовая генерация SEO-страниц: пока нет проверенного спроса и материала для каждой страницы; не применяется.

## Состав

1. Контекст `.agents/product-marketing.md` со статусом черновика; подтвержденные решения отдельно от гипотез.
2. Карта обучения `.author-voice/python-content-map.md`: темы, рабочие навыки, необходимые доказательства, предварительные статьи, текущий статус.
3. Рабочая карточка `.author-voice/templates/python-article-brief.md` и обновленный процесс `python-blog.md`. Два направления: тестирование и автоматизация задач на Python. Личные статьи показывают подход к работе без выдуманных технических достижений.
4. `archetypes/python.md`: создание черновика одной командой, обязательные метаданные и видимая пометка. Предметные навыки задаются в `competencies`, связь с подборкой — `career_track: python`.
5. `/docs/python/`: черновая точка входа с автоматически найденными материалами из обоих разделов. Ссылки с главной и блога появляются только когда раздел входит в текущую сборку. Пустая подборка имеет честное сообщение. Никаких страниц-заглушек для каждой недели.
6. Существующая статья получает только метаданные; ее текст и статус не меняются.

## Карта страниц и ссылок

```text
/ — главная, ссылка на Python когда раздел входит в сборку
├── /blog/ — хронологическая лента, ссылка на Python
│   └── /blog/2026-10-26-pytest-shared-list/ — прежний URL
├── /docs/python/ — подборка по метаданным и направление практики
│   └── /docs/python/YYYY-MM-DD-slug/ — будущие черновики по шаблону
└── /about/ — автор; подтвержденный профиль GitHub остается внешним контактом
```

Подборка ссылается на исходные статьи из обоих разделов; новые статьи содержат обратную ссылку на подборку. Сейчас Python-раздел и статьи — черновики, поэтому эти пути доступны в preview. Основная навигация сайта не меняется до решения о публикации. `docs` вне `content` и `.author-voice` — рабочие документы, не страницы.

## Границы и приемка

Без автоматической публикации, смены `draft: true`, внешних записей, изменения учебного кода или утверждений о достигнутом Senior/Lead. Подготовка статьи не решает за Дмитрия незавершенные задания. Контакты — только подтвержденный GitHub и существующая страница автора.

Проверки: обычная и черновая сборки Hugo, видимость подборки в обоих режимах, создание нового черновика через archetype, локальные ссылки, отсутствие рабочих материалов в сборке. Это проверка механики сайта, не авторское одобрение и не подтверждение навыков кандидата.
