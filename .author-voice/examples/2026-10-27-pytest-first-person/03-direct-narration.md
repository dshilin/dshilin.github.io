Два тестовых случая делают одно и то же: добавляют элемент в пустой список и проверяют результат. Первый проходит, второй должен упасть. Подвох — в слове «пустой»: ко второму случаю список уже изменился.

На этом примере я покажу причину ошибки, исправление и результат запуска. Здесь интересна не сложность кода, а вопрос: действительно ли независимы данные, на которых я строю проверки?

## Два случая — ещё не два списка

Начну с исходного примера:

```python
import pytest

shared = []


@pytest.mark.parametrize(
    "items",
    [shared, shared],
    ids=["first", "second"],
)
def test_items(items):
    items.append("login")
    assert items == ["login"]
```

В параметрах указаны два значения. Но оба — ссылки на один список `shared`.

При обычном последовательном запуске в одном процессе первый случай добавит `"login"` и пройдёт проверку. Второй получит тот же список, добавит ещё один элемент и сравнит `["login", "login"]` с `["login"]`.

| Случай | Список перед `append` | Список перед `assert` | Ожидаемый результат |
|---|---|---|---|
| `first` | `[]` | `["login"]` | Пройдёт |
| `second` | `["login"]` | `["login", "login"]` | Упадёт |

Для исходного варианта здесь я привожу ожидаемый результат по коду.

pytest не создаёт копии переданных параметров. Поэтому изменение объекта в одном случае может повлиять на следующий, если тот использует этот же объект. Это поведение описано в [документации pytest](https://docs.pytest.org/en/stable/how-to/parametrize.html).

Метки `first` и `second` помогают читать отчёт. Отдельных объектов они не создают.

## Как я исправил параметры

Я заменил `[shared, shared]` на `[shared, []]`. Второе выражение `[]` создаёт новый список, поэтому случаи перестают менять один объект.

Проверю исправление на полном примере:

```python
import pytest

shared = []


@pytest.mark.parametrize(
    "items",
    [shared, []],
    ids=["first", "second"],
)
def test_items(items):
    items.append("login")
    assert items == ["login"]
```

Я запустил этот вариант и получил:

```text
collected 2 items
2 passed in 0.23s
```

Это результат двух случаев из учебного файла `test_items.py`. Он подтверждает исправление для этого примера.

## Что ещё стоит улучшить

Первый случай всё ещё использует переменную уровня модуля. Если другой тест изменит `shared`, зависимость появится снова.

Для двух независимых пустых входов запись можно упростить:

```python
@pytest.mark.parametrize("items", [[], []])
```

Каждое `[]` создаёт отдельный список. Это дополнительный вариант из разбора; мой запуск выше относится к `[shared, []]`.

Присвоить существующий список другому имени недостаточно: нового объекта от этого не появится. Разницу между присваиванием и копированием объясняет [документация Python](https://docs.python.org/3/library/copy.html).

Для более сложных тестовых данных имеет смысл отдельно продумать, где и когда создаётся состояние каждого случая. В этом упражнении достаточно отдельных списков.

## Как проверить у себя

Сохраните полный исправленный пример в `test_items.py`. Если pytest ещё не установлен, выполните:

```shell
python -m pip install pytest
```

Затем запустите:

```shell
python -m pytest -v test_items.py
```

Чтобы проверить исходный вариант, замените `[shared, []]` на `[shared, shared]` и повторите запуск в новом процессе. Ожидаемый результат: первый случай пройдёт, второй упадёт.

## Что этот пример даёт для автоматизации

Прежде чем доверять автоматической проверке, нужно понять, откуда она берёт данные и кто успел их изменить. Иначе падение может говорить о состоянии самого теста, а не об ошибке продукта.

При похожем сбое я бы начал с трёх вопросов:

1. Где создаются входные объекты?
2. Какие случаи используют один объект?
3. Что остаётся после каждого выполнения?

Этот небольшой разбор показывает подход, который мне важен и в работе с ИИ: предложенное решение нужно понять, проверить на конкретном примере и обозначить, что именно подтверждает результат. Здесь подтверждены два учебных случая; поведение при повторных запусках в одном процессе и при распределении тестов между процессами я не проверял.
