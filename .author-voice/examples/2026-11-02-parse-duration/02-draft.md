Черновик — ожидает авторской проверки.

В учебном примере функция `parse_duration` получает строку с длительностью в миллисекундах и возвращает целое число. Я разбираю, какие значения проходят через преобразование, какие приводят к `ValueError` и чего эта функция не проверяет.

Исходный файл не указывает автора кода. Поэтому я описываю сохранённый пример, не приписывая себе его создание. Результат запуска в доступных материалах тоже не сохранён.

## От пробелов к целому числу

Функция состоит из трёх шагов: убирает пробелы по краям, проверяет оставшуюся строку методом `isdigit()` и преобразует её в `int`.

```python
def parse_duration(value: str) -> int:
    """
    Получает длительность в миллисекундах строкой и возвращает целое число.
    """
    value_stript = value.strip()
    if not value_stript.isdigit():
        raise ValueError(
            "Неправильный формат. Должна быть строка, представляющая целое число."
        )

    result = int(value_stript)
    return result
```

Например, для строки `" 2000 "` после `strip()` остаётся `"2000"`, а `int()` преобразует её в число `2000`. Пробелы внутри строки функция не удаляет.

По исходнику я могу вывести такое ожидаемое поведение:

| Вход | Ожидаемый результат по коду |
| --- | --- |
| `"1000"` | `1000` |
| `" 2000 "` | `2000` |
| `"0"` | `0` |
| `""` | `ValueError` |
| `"1.5"` | `ValueError` |
| `"-500"` | `ValueError` |
| `"3000ms"` | `ValueError` |

Это вывод из чтения функции, а не подтверждённый запуск.

## Что означает проверка `isdigit()`

На обычных строках она отсекает пустое значение, точку, знак минус и буквенный суффикс. Но `isdigit()` в Python принимает и некоторые Unicode-символы, которые выглядят как цифры, хотя не представляют число в десятичной записи для `int()`. Поэтому проверка сама по себе не гарантирует, что последующий `int()` завершится успешно. В таком случае `ValueError` возникнет уже внутри преобразования. Это поведение описано в [документации `str.isdigit()`](https://docs.python.org/3/library/stdtypes.html#str.isdigit) и [документации `int()`](https://docs.python.org/3/library/functions.html#int).

В сохранённом тестовом файле проверяются три допустимых примера и пять недопустимых: пустая строка, текст, десятичная запись, отрицательное число и суффикс `ms`. Тесты проверяют, что в недопустимых случаях возникает `ValueError`, но не сравнивают текст ошибки. Файлы прочитаны; тесты я не запускал, поэтому их фактический результат неизвестен.

## Где заканчивается контракт

В строке документации единицей названы миллисекунды, однако сама функция возвращает только целое число. Она не проверяет верхнюю границу и допускает `0`. Положительность длительности, разумный диапазон и формат записи — отдельные правила, которых в исходной функции и проверках нет.

Если такая функция используется для значения из конфигурации, аргумента командной строки или CSV, вызывающей части программы важно отдельно определить допустимый диапазон и то, как показывать ошибку пользователю. Это возможное применение примера, а не описание уже выполненной мной рабочей задачи.
